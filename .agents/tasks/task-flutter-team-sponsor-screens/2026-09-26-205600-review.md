### Sponsor-link throwing path now converges on the SnackBar

The v1 gap was that `launchUrl` can either return `false` or throw a `PlatformException`, and only the `false` branch reached the failure SnackBar. The fix wraps just the launch call:

```dart
if (uri != null) {
  try {
    opened = await launchUrl(uri, mode: LaunchMode.externalApplication);
  } catch (_) {
    opened = false;
  }
}
if (!opened && mounted) {
  ScaffoldMessenger.of(context)
      .showSnackBar(const SnackBar(content: Text('Could not open link.')));
}
```

Both failure modes now leave `opened == false` and hit the same `mounted`-guarded SnackBar, so a throwing failure is surfaced to the user instead of propagating uncaught. The pre-existing null/empty/unparseable guard is preserved. The catch is broad (`catch (_)`), which is appropriate here — any launch failure should degrade to the same user-visible message rather than being classified.

### The failure test is a genuine regression guard

`test/sponsors_screen_test.dart` gains a case that assigns a `FakeUrlLauncher(throwOnLaunch: true)` to `UrlLauncherPlatform.instance`, taps "Visit website", and asserts both `fakeLauncher.launchedUrls` is non-empty (the launch was actually attempted) and that the "Could not open link." SnackBar is shown. `addTearDown` restores the original platform instance, so the swap doesn't bleed into other tests. The fake lives in `test/support/fake_url_launcher.dart` as a `UrlLauncherPlatform` subclass whose `launchUrl` records the URL and throws a `PlatformException`; `url_launcher_platform_interface` was promoted to a direct dev dependency to support it.

To confirm this test pins the fix rather than passing incidentally, I removed the try/catch and re-ran only this case — it fails, because the `PlatformException` propagates and the SnackBar never renders. With the catch in place it passes. That is exactly the behavior a regression guard should have.
